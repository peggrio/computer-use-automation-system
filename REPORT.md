# Computer-Use Automation System

## Architecture

This implementation completes one read-only ParaBank workflow: verify that a transaction belongs to the requested account, find it, open its details, and return typed data. Python 3.11, Playwright Chromium, and a local Docker sandbox keep the system inspectable in one process. Banking data is read through the UI; request completion/status metadata establishes readiness, but response bodies are not used as a banking API.

Discovery and replay share `BrowserAdapter` for observation, resolution, actions, and checkpoints. Discovery supplies a reviewed natural-language goal and a finite control vocabulary to `gpt-5.4-mini`. The model chooses the action sequence through bounded observe → decide → act iterations. It sees sanitized facts and input references, not credentials or account values. A trusted verifier checks membership, detail identity, and output types before the compiler emits a capability. Compiler-added waits, extraction, and outcome guards are explicit trusted logic, not model discoveries.

The [real discovery bundle](evidence/discovery/dbce8a9d535c40a4ba91a003792854ea/) records seven model responses, six UI actions, nine compiled steps, and 6,894 tokens. The registry pins that generated artifact for model-free replay. The [acceptance report](evidence/acceptance/report.json) records 103 passing tests and eleven browser scenarios. This narrow application vocabulary makes validation tractable, but the CLI selects a named goal; arbitrary natural-language tasks and automatic discovery of new selectors are not implemented.

## Artifact schema

Four strict JSON contracts separate reusable behavior from runtime state: capability, surface profile, invocation, and run result. The [schema](contracts/schema.json) rejects unknown fields; semantic validation checks references, types, cardinality, output producers, and content pins. A capability includes immutable identity/version, provenance, typed inputs/outputs, logical targets, ordered actions, pre/postconditions, bounded retries, known outcomes, and final success conditions. Each output has one producer in the final extraction step. Money is a decimal string and dates are validated calendar dates.

For example, `{"type":"fill","target":"transaction_input","value":{"input":"transaction_id"}}` carries no recorded customer value. The independently versioned profile binds `transaction_input` to concrete controls and defines readiness rules. Invocation supplies values, session identity, budgets, and exact capability/profile hashes. Results distinguish success with typed outputs, business outcome, failure, and a live paused state. Outputs return to the Python caller; persisted summaries retain field names, not banking values. The [saved capability](evidence/discovery/dbce8a9d535c40a4ba91a003792854ea/capability.json) is separate from model request/response evidence.

## Determinism & error handling

Replay interprets only the pinned artifact. It validates inputs and compatibility, checks preconditions, resolves controls afresh, authorizes the actual action, waits for postconditions, then evaluates outcomes. It never asks the model to choose or repair a step. Targeting uses scoped roles/names, existing IDs, table structure, and exact decoded link-query comparisons; there are no test IDs or recorded coordinates. Fallback candidates are ordered: zero matches permits fallback, ambiguity stops. Unknown state is never evidence of absence.

Readiness checks successful completion of the relevant navigation/data-load generation. An empty table before loading is not “not found.” Missing accounts and transactions absent from the requested account are business outcomes. Expired sessions and bounded load timeouts are recoverable conditions; policy denials, ambiguous controls, application failures, and uncertain actions stop. Only waits retry, sharing one step deadline; clicks are not blindly repeated. Overall time/action budgets survive handoff. Final checkpoints and typed extraction must both pass.

Tests cover changed transaction/account inputs, cross-account mismatches, absent records, slow/failed loads, policy blocks, exhausted retries, ownership violations, and takeover. The full browser acceptance worker denies model imports and Python external socket connections; zero attempts were observed. Chromium traffic is separately constrained by the adapter policy. This establishes model-free execution for the exercised path, not identical banking data across time or a general process sandbox.

## Heterogeneity & multi-tenant

The seam is between logical workflow operations/checkpoints and the adapter's perception, resolution, and actuation. Current support is one browser profile using DOM and role-based locators on a table-based legacy-style app. Frames, OS accessibility, OCR, and coordinate execution are not implemented. The schema's accessibility-ID representation does not itself provide desktop support.

A future desktop adapter would bind logical targets to OS accessibility IDs/roles within a pinned application process/window. It must implement fresh observations, unique actionable resolution, typed reads, readiness rules, ownership epochs, and safe evidence capture. Where accessibility is incomplete, add an explicitly versioned screenshot/OCR strategy with confidence thresholds, display-scale/window geometry checks, and ambiguity rejection. Coordinates must be resolved from current observations, not replayed blindly. Desktop policy must restrict applications, windows, clipboard, file operations, and outbound effects; browser URL policy alone is insufficient. Legacy frames likewise need explicit frame context and readiness rules. Shared adapter conformance tests should precede any support claim.

For tenant reuse, retain vendor-level workflow semantics and vary reviewed surface profiles. Tenant configuration supplies origins, authentication references, locale, and trusted policy outside the capability. Proposed overrides would materialize a complete profile from a vendor base, app-release specialization, and tenant-specific bindings, rejecting conflicts and unknown fields. Validate, review, version, and hash that resolved profile before use; never apply hidden patches during replay. Branding/locator differences can use a new profile. Different business meaning or required steps need a new capability. No tenant resolver or cross-tenant deployment has been built.

Compatibility is explicit: schema/interpreter `1.0.0`, capability `0.2.0`, and profile `0.2.0` are distinct versions. Profiles reference an exact capability version; invocations pin both content hashes, and the registry pins policy. Current preflight rejects unsupported adapters/strategies and mismatched contracts; it does not dynamically discover vendor releases. Future release fingerprints and tenant canary runs should detect drift before rollout. Use major capability versions for incompatible I/O meaning, minor versions for compatible behavior changes, and patches for contract-preserving fixes. The current closed-field schema means adding outputs is not automatically compatible with old callers. Replay never selects `latest`, upgrades on a version range, or silently migrates old artifacts. Keep approved old bundles for rollback; unknown versions fail closed. Hashes provide integrity comparison, not signatures.

## Escalation & handoff

The headed takeover CLI pauses eligible blocked replay and exposes context in the terminal: capability, failed step/reason, expected state, evidence references, and remaining budget. Automation yields ownership of the same browser page/session. The operator repairs the state there, then explicitly types `resume` or `abort`. A recorder captures allowlisted click/input/change/submit/navigation metadata without text values. Session ID, request ID, and control epoch reject stale, foreign, or duplicate returns.

Resume seals input during revalidation, checks unchanged inputs/pins/policy and remaining budgets, then returns ownership and restarts this read-only capability from its entry checkpoint. It does not trust a claimed manual completion or skip membership checks. Lost sessions and policy faults cannot be bypassed; a watchdog expires abandoned handoffs. The retained takeover evidence uses a labeled simulated operator through real controls in the same session. The interactive mechanism is available, but that evidence does not claim a person participated. Discovery currently stops with safe failure evidence rather than entering this replay takeover controller. Remote operator authentication and enforced physical-input isolation are future work; this local terminal/browser interface assumes a cooperative trusted operator.

## Safety

Trusted policy allows only the local ParaBank origin, reviewed routes/query shapes, methods, and actions. Actual resolved controls and destinations are checked, including redirect hops. Login POST is narrowly scoped. Transfers, payments, account creation, downloads, unexpected surfaces, and external destinations are blocked; neither a model decision nor human resume grants extra permission. This demonstration intentionally avoids financial writes.

The API key stays in ignored `.env.local` and is used only by live discovery. Redaction occurs before persistence: closed metadata fields, sanitized model observations, and structural DOM failure snapshots with text/values removed. No raw screenshots, HARs, session storage, banking response bodies, or extracted outputs are retained. The acceptance scan checked 412 JSON/JSONL evidence files against known secret patterns, fixture values, canaries, and the local configured key, finding zero violations. Negative tests establish detection; this is not a proof against every unknown secret. Structural snapshots sacrifice visual detail for privacy. Evidence is local with restrictive permissions, but production retention, encryption, operator identity, and signed approvals remain unimplemented.

## Cuts

The working slice prioritizes contracts, real model discovery, deliberate replay outcomes, and live ownership transfer. It omits arbitrary-goal parsing, new-control discovery, desktop/frames/OCR execution, tenant infrastructure, remote operator consoles, financial writes, automatic artifact promotion, model-assisted replay recovery, and a deployed agent API. These would each require additional safety and compatibility evidence. The earlier unsuccessful real discovery attempt remains labeled, including its incomplete usage accounting; no synthetic run is presented as real discovery.

Next, implement a reviewed candidate-promotion tool, adapter conformance suite and second tenant variant, then a desktop proof of concept with application/window policy. Extend the same-session controller to discovery with explicit trace boundaries and budget handling. Add an authenticated operator service and signed, auditable artifact approvals before unattended multi-user deployment. The repository remains private as requested; publication and submission are separate user actions.
